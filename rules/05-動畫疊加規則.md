# 動畫疊加規則（選用）

> **這條標記為未實測**：跟其他規則檔不一樣，這條不是我們自己實際剪片驗證出來的，是參考社群公開分享的作法調整、還沒有在我們自己的專案上實跑過。用之前自己先做小範圍測試，不要直接套用在正式交付的專案上。

## 什麼時候才用

**預設不加動畫**。只有使用者在剪輯決策階段明確要求，或核准某個需要動態效果（HTML/CSS/GSAP動畫）的創意提案時，才進入這條規則。單純的靜態字卡/資訊卡不算在內，那個不需要動畫引擎，直接用一般的圖片疊加處理就好。

## 環境需求

- Node.js 22 或更新版本
- Bun
- 沒有被要求做動畫的專案，完全不需要檢查或安裝上述兩個工具——不要因為「以防萬一」就先裝起來。

## 操作原則

1. 動畫效果要在「剪輯決策」那一步（見 `SKILL.md` 第5步）提出具體提案並取得核准，不要先斬後奏、剪完才問要不要加動畫。
2. 動畫是疊加在畫面上的獨立圖層，跟主要剪輯的影像/音軌分開處理，不要混進同一份Premiere XML的clipitem裡（違反 `03-Premiere-XML規則.md` 第9條：不自創`<filter>`特效標籤）。
3. 動畫算繁重的選用需求，會拉長處理時間跟增加失敗點，交付前要讓使用者知道這是選用效果、預覽階段要特別確認動畫有沒有正常跑出來，不要假設「程式沒報錯＝畫面正確」。
4. 產生動畫素材時，只處理已核准範圍內的內容，不要自己延伸加其他沒提過的效果。
