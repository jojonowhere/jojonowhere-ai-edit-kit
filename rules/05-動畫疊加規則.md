# 動畫疊加規則

## 標準預設效果：懸浮光暈卡片（Floating Glow Card）

> 「剪接台」使用者確認喜歡、定案延用的標準視覺風格，不是眾多選項之一。**圖片／Logo／貼紙類疊加素材預設就套用這個效果，不用每次特別問**——內容類型判斷見 [`09-強調字貼紙內容確認規則.md`](09-強調字貼紙內容確認規則.md)；尺寸換算見 [`08-Remotion算圖管線.md`](08-Remotion算圖管線.md)。

**核心感覺**：懸浮（漂在畫面上）＋發光，但陰影不能重——太重會蓋掉發光感，變成單純的厚卡片。

### 動態版（Remotion，圖片類內容）

內容包在**背景全白、圓角的容器**（`FloatCard`元件）裡，疊兩層獨立`box-shadow`：

```
boxShadow: [
  `0 ${padding*0.5}px ${padding}px rgba(0,0,0,0.4)`,   // 陰影：偏移+模糊+黑，透明度0.4封頂
  `0 0 ${26 + pulse*16}px rgba(255,255,255,${pulse})`, // 光暈：置中不偏移，純白，隨pulse呼吸
].join(", ")
```

陰影在前光暈在後（層疊順序）；光暈一律純白（品牌色在亮背景會顯髒）；白色容器邊緣本身就是框，不用另畫border。動態參數：`glowPulse(frame,fps)=0.75+0.15*sin(frame/fps*2π/1.8)`（1.8秒一週期）；`floatSway`回傳`bobY`（週期2.4秒）與`rotate`（週期3.2秒，故意跟bobY不同週期避免死板），多張卡片用`phaseFrames`錯開相位避免同步晃；進場用`opacity+scale(0.9→1)`即可。

素材不適合塞白卡片（本身是透明小圖示）時，改用`floatGlow.tsx`的SVG filter版：對SourceAlpha做`feMorphology`＋`feMerge`做出「貼邊細框＋擴散柔光」，套在圖片`filter`屬性上，無額外白底、無陰影層。

### 靜態圖片版（照片/截圖做成PNG，非Remotion）

`scripts/floating_glow_card.py`已寫成可重用腳本，新素材直接跑，不要重新刻。實作是PIL疊圖，跟動態版同一視覺語言，反覆調整踩過的坑：

- **白邊要細**（原圖寬度~1.2%），厚白邊（~2.8%以上）會讀成「相框」蓋掉發光感；圓角可以給大一點（~4.5%）撐卡片感。
- **加一點隨手擺放的傾斜角度**（如-4.5°），完全水平顯得死板。
- **光暈疊4層漸層**（緊亮核心→中層→寬層→柔和外擴，透明度遞減、模糊半徑遞增），單層模糊只有「霧感」沒有「光感」，肉眼一眼能分辨。
- **【已知坑】光暈模糊前的原始尺寸要完整留在畫布內**：太大或貼齊邊界會先被硬裁切，模糊只會把裁切邊抹淡、不會消除，旋轉後變成明顯斜線/方框。畫布留白＝最寬光暈原始半寬＋模糊半徑3–4倍；腳本校正值是留白＝內容寬度0.95倍。
- **驗證邊緣要掃整條邊界帶**（如40px寬一圈），不能只看最後一像素——差一兩像素的殘留邊剛好會被單點檢查漏掉。腳本的`verify_edge_clean()`就是做這件事，跑出警告代表pad不夠。
- **物理限制非bug**：純白光暈疊在近乎純白背景上必然沒有對比、幾乎看不見。要任意背景都明顯，只能：光暈改非純白色（偏離現有規範，先問過），或改用Screen/Lighten合成。
- **Screen/Lighten合成**（需要任意/很亮背景都要看得出光暈時才用，預設仍用上面單檔案alpha做法）：交付拆兩個檔案——卡片本身一般透明PNG、NLE混合模式選「正常」；光暈另存黑底RGB圖、混合模式選「Screen」或「Lighten」。

### 沒有固定比例的內容（特效類，如爆炸/粒子）：寬高各自撐滿框

圖片/Logo要維持原始比例（見[`08-Remotion算圖管線.md`](08-Remotion算圖管線.md)），但特效沒有固定比例——用`min(width,height)`算擴散半徑會浪費非正方形框的另一維度（實測172×588窄框只用了172×172範圍，回饋「太小」）。改用X軸`width/2`、Y軸`height/2`各自獨立計算。

### 檔案位置

動態版：`remotion-starter/floatGlow.tsx`（SVG filter版）、`FloatCard.tsx`（白卡版）、`nativeMotion.ts`（動態語彙）——直接`import { FloatCard }`使用，不要重寫box-shadow公式。
靜態版：`scripts/floating_glow_card.py`（`python3 scripts/floating_glow_card.py 來源.png 輸出.png`，注意終端機有沒有印邊界警告）。

## 其他動態效果（選用、未實測）

> 跟上面「懸浮光暈卡片」不同：那是我們自己驗證、使用者確認喜歡才定案的；這節是參考社群做法調整、沒在自己專案實跑過（背後工具是HyperFrames，見`THIRD_PARTY_NOTICES.md`）。用前先小範圍測試，不要直接上正式交付。

**預設不主動加**。圖片/貼紙類套用懸浮光暈卡片是唯一不用問的例外，其他動態效果（HTML/CSS/GSAP）只在使用者於剪輯決策階段明確要求或核准時才做；純靜態字卡不算在內，走一般圖片疊加即可。使用者聊到「想加動態效果」時，先問一句「要不要用我們常用的懸浮光暈卡片效果？」——多數情況這樣就夠了；要更客製化的效果才走完整核准流程，動手前講清楚這條路未實測、風險較高。

環境需求：Node.js 22+、Bun，沒被要求做這類效果的專案不用檢查/安裝（懸浮光暈卡片不需要這兩個工具）。操作原則：動畫提案要在剪輯決策步驟（`SKILL.md`第5步）取得核准才做；動畫圖層跟主剪輯分開處理，不混進XML的clipitem（見`03-Premiere-XML規則.md`第9條）；預覽階段要實際確認動畫有跑出來，不要假設沒報錯＝正確；只做已核准範圍內的效果，不自行延伸。
