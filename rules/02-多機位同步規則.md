# 多機位同步規則（臉部＋螢幕錄影同時錄製）

**背景：兩支各自獨立的錄影裝置（例如手機相機錄臉、電腦錄螢幕）就算是同時開始錄，時間軸也不會完全對齊**——不只是「哪個先按下錄影」的固定秒差，兩台裝置的內部時鐘走速本身就有微小差異（即使都標稱同樣的fps），這個差異在短片段感覺不出來，但拉到超過一小時的長素材，會累積成看得出來的偏移，而且**偏移量會隨時間慢慢變大／變小，不是固定值**。

**已知會踩的坑**：只用單一固定秒差去對齊兩支素材（例如「螢幕永遠比臉部晚5秒」），在長素材上會失敗——不同剪點需要的修正幀數可能差到7-8幀、而且每段差得不一樣，這正是時鐘漂移沒被處理的症狀。

**正確做法**：
1. 用本機音訊比對（Python `librosa` + `scipy.signal.correlate`，跑在本機、不上傳不花錢）在兩支素材裡選3個以上的時間點（例如開頭、中間、結尾附近），對每個點各自算出當下的真實偏移秒數。可以直接用 `scripts/sync_multicam.py`（`python3 scripts/sync_multicam.py ref.mov other.mov --points 0 1800 3600`），下面2-4點的取樣、迴歸、輸出都已經包在裡面。
2. 用這幾個點的 `(時間點, 偏移量)` 擬合一條線性迴歸（斜率＋截距），得到一個隨時間變化的偏移量函式，而不是單一數字。
3. 生成每一個剪點時，各自代入該剪點在時間軸上的位置，算出當下該用的精確偏移量再套用——不要對整支素材套用同一個修正值。
4. 交付前用擬合結果反推「整支素材累積漂移了多少」講給使用者聽（例如「64分鐘裡只累積漂移0.1秒，不到3幀」），讓使用者知道這次對齊的精確度，不要只說「已經對齊了」。
