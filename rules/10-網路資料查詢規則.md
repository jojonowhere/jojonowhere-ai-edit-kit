# 網路資料查詢規則

> 這條規則讓Claude在走剪輯流程時可以主動查網路資料（技術問題、參考風格、最新版本資訊），不是額外要裝的軟體——Claude Code本身就內建瀏覽網頁的工具，不需要另外安裝套件或外掛。

## 什麼時候該查

1. **技術問題卡住、或不確定某個工具的最新用法時**：例如某個ffmpeg/Remotion參數效果不確定、某支工具版本更新後行為改變、要處理一個之前沒遇過的錯誤訊息。查完直接應用，不用每次都先問過使用者才查（純查資料不是有風險的動作）。
2. **使用者要求參考特定風格/趨勢時**（例如「幫我看一下現在流行的轉場效果」）：查完把找到的參考方向講給使用者聽、確認要不要照做，不要查完就直接套用在使用者的正式素材上。
3. **需要確認某個外部服務/工具目前的狀態**時（例如ElevenLabs API的方案/額度規則是否變動、Remotion官方文件的最新語法）。
4. **使用者貼參考影片連結、想要分析畫面/節奏/手法時**：優先用`/watch`plugin（見`THIRD_PARTY_NOTICES.md`，`setup.sh`第4步會自動裝，前提是本機有獨立版Claude Code CLI）。**如果現在這個session偵測不到`/watch`（例如純Claude桌面版環境，沒有獨立CLI）**，不要就這樣說做不到——改用一般網頁瀏覽能力盡量讀那個連結頁面上看得到的資訊（標題、描述、留言區討論、公開字幕/逐字稿等文字內容），並且要老實跟使用者講清楚：「這個環境沒辦法真的逐格看畫面/聽音訊，只能看到頁面上的文字資訊，想要更準的分析可以裝`/watch`」——同時可以引導使用者裝：確認本機有沒有`claude`這個獨立CLI指令，沒有就帶著裝（`npm install -g @anthropic-ai/claude-code`），再跑`claude plugin marketplace add bradautomates/claude-video && claude plugin install watch@claude-video`。不要在使用者還沒實際貼連結、只是被動列出能力清單（例如開場問候）的時候就先講這堆細節，那個時機只講「可以貼連結分析風格」這句結論就好，實際遇到才展開解釋跟引導。

## 怎麼查

直接用Claude Code內建的網頁瀏覽/搜尋能力，不用另外安裝MCP或npm套件。純讀取網頁內容不牽涉使用者素材，不用另外取得同意——這跟「上傳素材到ElevenLabs」是不同層級的風險，上傳素材才需要每次重新明確同意（見 [`SKILL.md`](../SKILL.md) 安全原則）。

## 安全原則

1. **不要把使用者的影片/音檔/截圖內容貼到查詢字串或第三方網站裡**——查資料是查「怎麼做」，不是把使用者的素材外流出去確認。
2. **這個repo裡已經實測驗證過的規則，優先權高於網路上查到的通用建議**：`rules/`裡很多規則是踩過坑、實測修正過的（例如ProRes4444在macOS上要`--hardware-acceleration=disable`才有透明通道、ffmpeg crop filter的time-varying參數其實不會逐幀生效），這類細節網路上的教學文章常常沒提到、甚至寫錯。查到的資訊如果跟這個repo已驗證的規則衝突，先假設是查到的資訊沒考慮到這個環境的特殊狀況，不要直接覆蓋掉已驗證的做法，要交叉確認或問使用者。
3. **引用/參考別人網站的內容時，不要整段照抄**——摘要用自己的話講，需要引用原文時只取簡短片段並附來源，尊重原作者的著作權。
