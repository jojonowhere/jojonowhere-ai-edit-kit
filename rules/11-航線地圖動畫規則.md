# 航線地圖動畫規則

> 使用者確認喜歡、定案延用的樣式（來自 `edit_cheap_flights` 專案的 `TaiwanJapanRoutes.tsx`）。跟 [`05-動畫疊加規則.md`](05-動畫疊加規則.md) 的「懸浮光暈卡片」是不同的視覺語言——這個是給「地圖＋航線」這類地理資訊動畫專用的，不要套用懸浮光暈卡片的白卡/crisp ring做法。共用的算圖指令、透明通道驗證見 [`08-Remotion算圖管線.md`](08-Remotion算圖管線.md)。

## 核心規格

- **國家／地標形狀**：真實海岸線資料（Natural Earth，經 `world-atlas` npm package，public domain），**不要手畫**——每個地標各自獨立投影塞進畫布，不用維持地標之間的真實相對比例。黑色描邊（`stroke="#000000"`）＋**實心淺灰色填滿**（`fill="#d6d6d6"`，不是半透明白）。
- **航線本身是純發光線，不能有黑色描邊**：`stroke="#ffffff"`、細線寬（約2.5px，這是「精緻的圖」，不是霓虹招牌）、套用**輕量**版的glow filter（單層`feGaussianBlur stdDeviation≈2`就夠，不要疊多層重blur——已經實測疊太多層/太粗的線看起來「糊」不是「光」，使用者原話「光暈太多了」）。
- **文字／地名標籤：預設不要**，只留位置的圓點標記（黑色外圈+白色發光內圈的雙層`<circle>`）。使用者要地名時才加回來，加的話沿用舊版做法（黑色實色字、無描邊、無stroke）。
- **整體要有懸浮感**：用一個包住整個`<g>`的組合filter（陰影offset+blur+黑，透明度~0.4；再疊一層柔和白色glow，`feMorphology dilate`+`feGaussianBlur`，**不要加crisp ring**——crisp ring是懸浮光暈卡片專屬的硬邊做法，套在地圖上會變成不想要的白色描邊，使用者原話「不要描白邊」）。

## 多條航線：依序播放，不要同時畫

**預設所有航線同時畫（lockstep）是錯的**，觀感呆板。改成依序、錯開時間播放：

```ts
const ROUTE_STAGGER = 14;      // 每條航線間隔幾幀起飛
const ROUTE_DRAW_FRAMES = 40;  // 單條航線畫完要幾幀（實測24幀「太快」，40幀是使用者確認過可以的參考值，不同專案節奏不同可以調，但別直接沿用24）

CITIES.map((city, i) => {
  const start = i * ROUTE_STAGGER;
  const cityProgress = interpolate(frame, [start, start + ROUTE_DRAW_FRAMES], [0, 1], {...});
  // 這條線自己的 strokeDashoffset、自己的目的地marker，都吃這條線自己的 cityProgress
});
```

目的地marker也要各自跟著自己那條線的完成時間點`opacity`淡入，不要全部共用同一個`endpointsIn`。

## 【已知的坑】沿線移動的光點一定要用「弧長」定位，不能用貝茲曲線的參數t

**症狀**：加一個沿著航線飛的光點（模擬「飛機飛過去、照亮周圍」的感覺）時，如果直接用二次貝茲曲線公式 `B(t) = (1-t)²·P0 + 2(1-t)t·P1 + t²·P2` 代入跟`strokeDashoffset`同一個`progress`值去算光點位置，**光點會跟線的筆尖對不齊**——線畫完了光點才追過去，或光點超前線的筆尖。使用者原話：「光暈沒有跟線一起畫出來，線先畫好了，光暈才飛過去，那個飛得不理所當然」。

**原因**：`strokeDashoffset`的動畫是均勻依照**實際弧長（arc length）**在推進的（SVG dash pattern的單位就是路徑的實際長度），但貝茲曲線的參數`t`均勻遞增，並**不**對應弧長均勻遞增——曲線彎曲的地方，同樣的Δt掃過的弧長比較長或比較短，取決於控制點的幾何關係。所以「t=0.5時筆尖畫到哪」跟「這條線畫了50%長度時筆尖在哪」，在彎曲的線上根本是兩個不同的點。

**正確做法**：預先算好一張「t → 累積弧長」的數值對照表（曲線是靜態的，起訖點跟控制點不隨frame變動，這張表只要算一次，不用每幀重算），光點位置改成查表找出「畫到某個弧長比例時，對應的t是多少」，再代入貝茲公式：

```ts
function buildArcLengthTable(from, ctrl, to, samples = 120) {
  const table = [{ t: 0, len: 0 }];
  let prev = pointOnQuadratic(from, ctrl, to, 0);
  let cum = 0;
  for (let i = 1; i <= samples; i++) {
    const t = i / samples;
    const p = pointOnQuadratic(from, ctrl, to, t);
    cum += Math.hypot(p.x - prev.x, p.y - prev.y);
    table.push({ t, len: cum });
    prev = p;
  }
  return table;
}

function pointAtArcFraction(table, from, ctrl, to, fraction) {
  const targetLen = fraction * table[table.length - 1].len;
  for (let i = 1; i < table.length; i++) {
    if (table[i].len >= targetLen) {
      const a = table[i - 1], b = table[i];
      const segFrac = (targetLen - a.len) / (b.len - a.len || 1);
      const t = a.t + (b.t - a.t) * segFrac;
      return pointOnQuadratic(from, ctrl, to, t);
    }
  }
  return pointOnQuadratic(from, ctrl, to, 1);
}

// 光點位置：pointAtArcFraction(table, from, ctrl, to, cityProgress)
// 不要用：pointOnQuadratic(from, ctrl, to, cityProgress) ← 這個就是踩坑的寫法
```

這幾個函式已經整理成共用檔案 `remotion-starter/routeMapGeometry.ts`（`arcPath`／`pointOnQuadratic`／`buildArcLengthTable`／`pointAtArcFraction`），新專案直接 import，不要複製貼上重新刻一份。

`cityProgress`（含easing）兩邊要用**同一個值**：`strokeDashoffset`那邊算的是`DASH * (1 - cityProgress)`，光點這邊代入`pointAtArcFraction(..., cityProgress)`，這樣不管有沒有加easing、easing曲線長怎樣，兩者永遠對得上。

**光點本身的畫法**：一個小的高亮核心（`r≈4`，套`dotGlow`那種近距離blur）＋一個大很多、更柔的「照亮背景」光暈（`r≈30`，用單獨一個大blur值、例如`stdDeviation≈22`的filter，讓它讀起來像光源在照亮周圍，不是線本身的一部分）。光點的淡入淡出用`interpolate(cityProgress, [0, 0.08, 0.85, 1], [0, 1, 1, 0], ...)`，讓它在該條線開始畫的瞬間快速浮現、快抵達終點前開始淡出、跟目的地marker的浮現銜接。

## 渲染前後的驗證

改完一定要先出**多張靜態截圖**（`npx remotion still ... --frame=N`，挑幾個涵蓋「單條線畫到一半」「多條線交錯進行」「全部畫完」的frame）分別疊黑底跟亮底看效果，不要憑程式碼邏輯猜對不對就直接跑正式的ProRes渲染——正式渲染一次要幾分鐘，static frame check幾秒鐘就有答案，來回成本差很多。疊底檢查指令：

```bash
ffmpeg -y -f lavfi -i "color=c=0x0a0c14:s=<寬>x<高>" -i 素材.png -filter_complex overlay -frames:v 1 -update 1 輸出.png
```

正式渲染指令、透明通道的四個必要參數，見 [`08-Remotion算圖管線.md`](08-Remotion算圖管線.md)（本專案渲染時沒加`--hardware-acceleration=disable`也驗證出透明通道正常，但那份文件記錄過這個參數在某些情況下是必要的、省略有靜默丟失alpha的風險——之後遇到alpha消失、`pix_fmt`變成沒有`a`的情況，先加回這個參數再排查其他原因）。
